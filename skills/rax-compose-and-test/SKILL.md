# RAX：函数合并与新摆位测试

把成功经验转成可复测的普通 Python 控制器。交付的是同一 `ctx` 上串联的 `main(ctx)`、备份、版本身份和真实运行记录；不是重新让主 Agent 在每个动作之间规划，也不是默认拼接连续轨迹。

## 按任务读取

- 合并、演练或接续测试：读 [workflow.md](references/workflow.md)，其中区分上游要求与本项目选择。
- 接入本人的 5090/Piper：再读 [piper-setup.md](references/piper-setup.md)，先核对现场与当前文件；不能把这些数值复制给另一台机器人。
- 遇到慢、遮挡、视觉兜底或反馈异常：读 [lessons.md](references/lessons.md)，按实测证据定位，避免重复以前的问题。
- main 已跑通但动作断续、闭爪/试抬后等待明显：读 [main-trajectory-optimization.md](references/main-trajectory-optimization.md)，区分函数合并、命令合并和速度连续，按实测时间线优化独立候选。
- 运行 Web / 多摆位测试：读 [scale-testing.md](references/scale-testing.md)。本 skill 是操作知识，不是自动执行硬件的授权。

## 工作顺序

1. 找到实际成功探索的报告、人工协助记录、逐函数工作副本和冻结版本。不要仅依据“进程返回 0”确认成功。
2. 备份当前演练副本与将修改的宿主接口；保存 SHA256 和嵌套代码仓库 commit。修复在可写副本完成，冻结版本不覆盖。
3. 每个函数接收 `ctx` 和明确输入，返回 `ok / measured / why` 或同等报告；使用后端状态、FK、路径检查与按需观测完成前置条件及结果检查。普通规则不足时才调用视觉模型，隐藏接触不能要求单张图像证明。
4. `main(ctx)` 顺序调用已验证函数，首个失败返回报告。各函数共享传入的 `ctx`，不创建额外控制连接。保留闭爪、试抬、释放边界；是否进一步合并轨迹是另一项验证工作。
5. 离线重放成功和失败帧、边界/异常测试、版本/资产一致性检查。离线通过不能替代真机验收。
6. 原生设备入口复位；操作者重新摆位；每轮从新观测定位，不沿用上轮坐标。一次运行一个控制器，不在脚本运行中另发直接动作。
7. 每轮记录版本、摆位、结果、阶段耗时、模型次数、实际运动回执和失败原因。人工接管或补充关键事实的轮次标为 assisted/debug，不计为无人工自主成功。出现含糊执行结果先核对状态，不能盲目重新执行 main。

## 决策边界

- 刷新网页、读 skill、连接只读相机不等于授权运动。已有用户明确授权内的操作继续完成，不重复索要同一确认。
- 中断 Python 不代表机械臂已停。用设备原生 Stop/disarm 并查反馈；不要靠 kill 脚本代替停止。
- 只读重连不能抢占其他任务的设备；回零使用原生控制器，不让探索模型生成回零路径。
- 新场景必须重新测量。同一次有界接近中可保留已绑定的三维目标跨函数/遮挡使用；物体移动、接触异常、关联丢失或重启后失效。
- 数值到位、路径可执行和图像定性判断各自说明能证明什么。命令下降到预测高度不等于测得支撑力；腕部未做手眼标定时不能把其 optical 点直接作为 base 目标。
- 区分工作区位置边界、单次位移上限、完整位姿 IK 和关节限位。本机左法兰 X 上限已为 500 mm，单次位移仍为 400 mm；范围内不代表任意朝向都可达。预检必须使用与执行层相同的工作区，并保留 IK/碰撞拒绝原因，不能把到位容差当作关节限位余量。具体范围及 J4 失败案例见配置与经验参考。
- 本 skill 不自动把工作经验晋升为 RAX 跨会话 executable library。若用户要入库，另按上游 skills-lib 格式、证据和 checker / library_merge 流程办理。
