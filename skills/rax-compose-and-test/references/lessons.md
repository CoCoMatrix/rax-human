# 问题、修复及尚未解决的边界

| 现象 | 原因 / 已采用处理 |
|---|---|
| 空载接近也反复视觉失败 | 问题要求图片证明隐藏爪底间隙、两帧间绝无接触。改由实测关节、FK、安装几何和路径检查承担可计算条件；图像只判断可见任务事实。 |
| 遮挡后每段重新识别杯沿，模型往返多 | 同一次接近的三维目标跨函数保留；初始定位一次，后续按需观察。场景移动/异常重新绑定，跨轮不复用坐标。 |
| 试抬看不出是否离桌 | 试抬改为经验 40 mm。比较杯子相对橙垫关系、轮廓大体位置、阴影/整体上移，不要求看见整圈杯底。视觉定性与精确支撑证明分开。 |
| 一侧橙垫 centroid 移动导致误拒绝 | 遮挡使可见面积变化，不能把 centroid 移动当硬件错位。使用共同可见区域及杯体大范围关系，保留明显矛盾的拒绝。 |
| L 轮头部深度质量不够导致兜底 | 杯沿深度 P90-P10 达 16.849/14.020 mm，超过 14 mm 的精确深度规则；腕部本可定性判断，却被头部深度前置门挡住。rc9 让腕部规则独立判断，可靠头部高度若明显矛盾仍拒绝，不放松精准深度质量标准。 |
| 不需要腕部深度也调用 FFS | 原先未产生可消费 ROI 却发请求。仅有 unresolved fact 与有效 wrist_relation ROI 才调用左腕 FFS；未做手眼时仍只能 optical-frame 使用。 |
| 最后放置因头部杯沿被遮挡失败 | 使用真实释放/退开回执、目标 XY/Z、张爪状态与腕部杯体/杯口定性关系。可说“放置大体合理”，不能伪称测得完整支撑接触。 |
| J5 小幅变化反馈仍是 0 | 厂家确认关节反馈有约 0.3° 变化量过滤；电机角有差但未获完整变换，不把差值随意当零偏扣掉，不过滤零值。用户最终指定 0.01 rad；此配置不是高精度微动作验收结论。 |
| TLS 错误导致任务退出 | 旧 17890 代理不是当前 XQNetwork 链路；使用 7892。对 SSL EOF/RemoteDisconnected/ConnectionReset 仅一次新连接重试并计预算，不重试鉴权/配额/证书错误；机器人动作不随网络自动重发。 |
| 状态漂移/观测绑定过严 | 统一用户明确选定的关节阈值，并修复观测重新绑定入口；不改采样时间戳冒充新鲜度。 |
| 衔接慢 | 分解成 path check、previous ack、staging、first SDK、settle、response；减少重复交接和小分段，不用跨动作轨迹拼接掩盖耗时。 |
| 新摆位 IK 和碰撞通过，却在下发前被工作区拒绝 | 旧左法兰 X 上限 360 mm，目标约 369 mm；原纯路径工具没有报告工作区。rc10 改为用户指定的 X 上限 500 mm，路径预检和执行层共用工作区采样，准备目标在动作前先检查。不是删除工作区检查。 |
| 在 500 mm 内仍出现 IK 无解 | 本轮固定向下朝向的当前解支需 J4≈89.55°，模型限位 89°。半段/四分之一段仍超限，不能靠继续缩段或放大到位容差解决。只读对照同点绕基坐标 Y 轴调整 −1°可解，但完整路径/抓取仍未验证；这是待修策略，不是已部署修复。 |
