## 问题到解决方法

| 现象 | 原因与当前处理 | 证据/仍需注意 |
|---|---|---|
| 空载准备反复失败 | 图片被要求证明隐藏间隙或全过程无接触；改用反馈/几何检查可计算条件，视觉仅看相关可见事实 | 不把未建模环境自动视为空 |
| 进入遮挡后无法继续 | 每段强制重测近侧杯沿；保留本轮带身份的三维目标 | 新摆位、目标移动或 owner/标定变化需重建 |
| 刷新深度后仍过期 | 语义请求长尾，旧像素与新深度混用风险；刷新后重新关联轮廓、状态和标定 | 有界刷新，不改时间戳 |
| 启动读代码过多 | 入口要求过宽，Agent 反复提前读取后续源码 | 缩到当前函数/紧凑报告；旧提示仍需与最新实际入口对齐，尚非全部行为验收通过 |
| 10/20 mm 试抬难判断 | 杯底遮挡且变化太小；使用至少 40 mm，前后定性比较 | 不是靠必须看见杯底的严格标准，也不是无条件接受 |
| 把历史参考图当当前 | 帧排序、标签、分辨率及像素换算混淆 | 当前优先、逐图标签、等尺度前后比较、归一化坐标只转换一次 |
| 杯垫身份混淆 | 图上另一个圆物体被识别为目标 | 绑定本轮初始杯垫、owner、bridge、几何和上一实测状态 |
| 腕部质心偏移触发兜底 | 遮挡、浅色杯体使固定颜色/像素阈值失效 | 共同可见橙垫区域、中间杯壁和整体关系；加入明显滑落/错位反例 |
| 头部深度差导致腕部也失效 | 定性腕部规则被精确头部深度有效性前置条件挡住 | rc9 独立腕部定性证据，可靠矛盾仍拒绝 |
| 两路图相差 >0.25 s | 异步采集不总是近同时 | 在已验证静止区间可做定性联合，保持身份/年龄/无动作检查，不做跨时像素融合 |
| 无用调用腕部 FFS | 没有能消费深度的 ROI 仍发请求 | 只针对未解决事实和有效消费区域调用；无手眼不生成 base 目标 |
| 试抬后 TLS 异常导致错误恢复 | 动作已执行，后续感知失败；父报告曾误写未执行 | 依据真实动作回执保存执行事实，恢复不重抬；新连接与有限只读请求重试 |
| 近零 J5 反馈变化为 0 | 厂家确认约 0.3° 变化量过滤 | 不滤零、不把电机差值擅自当零偏；用户逐步改到 0.01 rad，牺牲微小动作判别精度 |
| 关节到位但观测绑定失败 | 不同层使用不同漂移阈值/恢复入口 | 核对有效到位、绑定、预检配置，按本机 0.01 rad；不是放宽硬限位 |
| 1.2 s 级下发等待、动作不连续 | 预检、轮询、交接和持稳叠加 | 自动时长，减少重复交接/不必要小段；用户选 0.3 s 持稳，不拼接连续轨迹 |
| READY 有了但缺 rax_motion | 启动状态竞争 | 等完整且新鲜 owner 状态再核验；R31c 启动验证通过 |
| 会话预算与深度包数冲突 | 3600 s 对应 11160 包超过 10000 上限 | R31 改为 3000 s/9360 包启动；预算全链路自动联动不能写成已全面解决 |

## 验证改动的方法

先离线验证相关分支，再在用户授权范围内做逐函数真机验证。无需每次重跑全部工具验收；新增失败或改变控制契约时扩大检查。

| 改动 | 有意义的离线对照 |
|---|---|
| 遮挡/普通视觉规则 | 用真实遮挡帧判断合理抓取，并加入空爪、明显滑落、杯体错位、可靠头部矛盾；不能只验证成功帧 |
| 本轮三维目标保留 | 正常同轮跨函数可用；换 owner、换标定、目标移动/身份不明则失效；新深度不沿用旧像素 |
| 多视角时间差 | 合法静止区间可联合；期间有动作、图像过旧、身份变更不能复用 |
| 按需 Gemini | 普通规则通过时 0 次；不足才调用；格式错误、截断、unknown 不被直接当成功 |
| 网络恢复 | 只读请求有限重试并记 provider 尝试；动作已经完成时不重播；预算和认证错误保持可见 |
| 结果与恢复 | 感知失败仍保留 executed 回执、实测位置与可能持物状态；只重入相关函数 |
| 参数/工作区 | snapshot、预检和实际执行一致；500 mm/400 mm 含义不混，关节限位不放宽 |

不要为展示“离线通过”虚构现场精度；mock 能验证分支和接口，不能证明真实抓取。

## 每次函数调用记录什么

记录 session/run ID、代码 commit、参数/几何身份、函数及实际模块、场景来源、起止时间、输入报告与输出报告、实际动作、实测关节/夹爪、结果/错误和人工帮助。时间至少分为：

- 主 Agent 请求次数、累计请求时长与函数间隔；与函数并行部分不重复相加。
- 函数 wall time、普通感知、IK/预检、动作交接、SDK 运动、持稳。
- Gemini 逻辑调用次数、provider 尝试、累计/尾部时延、FFS 次数。
- 会话总时间、整段 main 时间、Prepare 时间分别记。

优先用现有 JSON 报告、memory/RUNS、连续录像和 Web 实验表，不添加另一套执行框架。Web 的整段记录不能直接替代逐函数演练的主 Agent 时间账。

1. 当前旧演练提示与新函数 imports/3 mm 配置需要启动时对齐；新 skill 是明确入口的文档，不是已经修改并实测运行时提示。

3. M 轮静态碰撞缓存因 `0.002` 与 float32 `0.0020000000949949026` 表示差未命中；需统一实际表示后验证，不能靠随意取整扩大匹配。

5. 左腕手眼、完整环境建模、不同杯型/摆位覆盖及完整工具特性验收仍有各自范围；单次零 Gemini 不证明普遍泛化。
