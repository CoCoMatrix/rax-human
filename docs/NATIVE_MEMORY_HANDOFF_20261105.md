# RAX 原生任务经验与证据交接修复

本次沿用 Franka `experience-memory/SKILL.md` 及 `references/format.md`；两份源文件未修改。
没有新增任务记忆服务、存储协议、自动摘要、经验晋升或控制框架。
跨任务技能仍走既有 `continual-learning`、会话分支、上游检查器与 `skill_library_merge`。
直接探索成功不等于无人接管代码成功，不满足条件的过程不标成 verified。

## 后续探索的操作顺序

1. 在当前任务工作区继续或恢复时，按原生指令先读 `memory/PROGRESS.md` 和
   `memory/INDEX.md`，只检索适用技能；当前观察和工具契约优先于旧经验。
2. 得到有用的可见结果后立即更新 `TIPS.md`：条件、动作或相对位姿、效果、帧路径。
   失败和人工辅助如实记录；修订同一条经验，不堆积互相矛盾的参数。
3. 有证据支持的可复用过程才整理到 `memory/skills/<slug>/SKILL.md` 和
   `evidence.json`，更新 INDEX。只有全部任务条件有证据时用 task-confirmed。
4. 中断前保存实际进度、未完成事项、失败与证据。中断/退出码/夹爪到位不推断成功。
5. 同一任务切换到新的物理会话时，使用现有 `--continue-from <已结束会话>`；
   它接续该会话的原生记忆和引用文件，不读取旧位置作为新目标，也不把旧代码当控制器运行。
   真正新的探索使用 task config 明确指定的已整理记忆来源，不自动猜测最新目录。
6. 演练使用可写候选的记忆、代码和证据。满足原生技能库贡献条件的可执行过程，
   才按 continual-learning 的 draft/verified 规则提交、检查并合并。

## 修复的文件交接缺陷

- `piper_handoff.import_memory` 复制原生 memory，同时复制其 evidence.json 引用的帧、
  动作账本以及核心任务笔记中明确引用的证据文件，保持相对路径不变。
- 来源不存在、路径越界、软链接或目标文件内容冲突会报告错误；不使用占位图片。
- 选择的记忆来源在启动设备前检查；收尾再次检查并记录独立的
  `memory_evidence_valid`，不把文件检查当任务成功判断。
- 新工作区的记忆保持可写。冻结版本只读。
- 蓝杯的新探索来源改为现有 v0.3 可写工作副本的已整理 memory；不再只加载最初口述种子。
- 未增加自动回写或自动汇总层。新会话成果保存在本会话 memory，续接必须选择正确来源。
