## 流程上的问题

本轮目标由主agent直接选取，没有在这一不确定可达性的转向边界先做只读候选检查。
收到无解后，agent将“不得绕过拒绝”解释为结束物理探索，直接收尾，没有利用工具回执
`no_action_executed=true`、`control_uncertain=false`、`episode_ended=false` 的区别。
严格停止反馈异常是必要的，但纯规划无解应先保持、只读搜索合法候选、核对当前场景与
完整路径后再决定是否可继续，不能一律等同硬件失控。历史R12也有只读候选检查修正
无解的记录。此处仅分析，尚未修改提示词、运行入口或控制参数。

后续最小改进：在方向转换边界批量只读检查少量目标候选并保留关节余量；统一明确
规划拒绝与真实控制异常的恢复语义；当前观测仍用于场景和路径检查。不会将历史绝对
坐标写成固定杯子控制器，也不会仅凭IK成功声明避碰安全或直接执行降低20mm的动作。

拆分需要上游证据。IK失败搜索本身约0.1s。
