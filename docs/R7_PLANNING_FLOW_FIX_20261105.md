# 转向候选与规划拒绝处理修正

已同步5090个人RAX工作仓库。只修改现有技能/提示词、求解器异常类型及公开错误回执，
没有新增任务规划框架、自动重试或真机控制器。本次没有启动owner、相机、RAX agent
或发送动作；最后物理状态来自用户要求停止后已核验的XPolicy Prepare。

## 行为变更

1. 每次新的方向转换先以当前物体定位、测得关节状态联合选择法兰位置和朝向，在
   一个短Context调用中只读比较少量FK/IK候选。优先检查物体上方或邻近的过渡区域，
   不再要求远处固定转向点或“先转到底再横移”的固定顺序。检查关节余量、完整手指
   包络、关节插值路径及CAD外场景；缺少定位先补观察，不抄历史绝对坐标。
2. 真实MoveIt返回匹配请求ID、hardware_writes=0、明确MOVEIT_NO_IK_SOLUTION后，
   适配器保留IKNoSolution类型，公开回执标记recovery_action=replan_read_only。
   只有validation阶段、未派发且没有此前control_uncertain时才给此标记。
   它仅允许保持当前位置并只读比较不同合法目标，不会自动重试/派发，不清除旧异常。
3. 协议/连接/校验失败、状态绑定拒绝、真实反馈或跟踪异常不属于此分支。停止物理
   探索，观察并记录。IK成功也不等于场景安全、动作成功或杯子任务成功。

泛用错误层只读取设备异常提供的恢复类别，不包含Piper/Franka或杯子条件。
实际工作仍是RAX原生manual-robot-control：agent通过现有工具探索，随后从成功
经验整理函数；候选检查规则不等于加载现成杯子控制器。常规已知可达的平移不新增
固定IK或辅助视觉往返。当前用户的仅离线要求优先；旧提示词中的“立即探索NOW”已移除。

## 经验库核对

R7实际读取了R12 placement经验、TIPS及工具表，没有导入旧控制器。R12经验主要覆盖
对齐后的抓取、试抬、搬运、支撑释放；“保持向下姿态”描述已夹持后的搬运，并未强制
空载准备时先在旁边完成转向。R7实际先上抬30mm，再同时平移与分段转向，未进入抓杯
下降阶段。选点没有建立抓取高度，随后主agent临时选择了旁侧高位转向目标；没有把
杯子定位、过渡位置和朝向作为一组候选检查，最终目标在当前分支要求J4超过模型上限。
不能因此把那几段动作晋升为所有布局的必经经验。
