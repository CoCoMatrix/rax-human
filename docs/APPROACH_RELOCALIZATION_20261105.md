# v0.3 接近函数修复与演练记录

2026-11-05：只修改可写工作副本及杯子任务说明；冻结 v0.1/v0.3 不变。

## 已定位原因

- 原 `approach` 接收主 agent 给出的 delta/position，没有从当前布局计算任务目标。
- 原视觉解析器直接接受 contradicted；“overlaps/contacts”被当作真实接触，未要求区分投影与物理界面。
- 原 ok 表示一次动作和检查通过，不能表示接近目标已完成。
- 上轮定位输出存在 normalized/pixel 混用。继承并验证了上轮可写代码中的归一化提示、原图轮廓校正和实际深度支持方法。

## 修改

- `perception.visual` 对 target_separation 使用逐相机 clear_gap/projection_overlap/direct_contact/occluded；直接接触需要具体物理证据。保留原始模型结论。
- 仅重叠或缺证据返回 unknown；另一相关视角的清晰间隙可以解除歧义。明确接触、实际障碍仍阻止动作。unknown 不转换为 clear。
- 明确头部为俯视、腕部随末端旋转，不能用图像竖直方向判断杯子是否侧倒。明确 JSON 嵌套位置，并兼容同名证据容器。
- `approach(ctx, {"phase":"hover"|"entry"})` 内部重新定位、计算 TCP/法兰目标；不接受历史 delta/position。每次最多一个55mm分段。
- 候选目标：hover 的 TCP 在杯沿上方50mm；entry 的接触中心在沿下10mm。这是待真机验证的任务参数，不是碰撞间隙保证。
- 检查安装 TCP 身份、向下姿态、开合轴与杯壁法向、12–20mm开度、低位横移、定位状态时效和深度一致性。SDK/运动容差未改。
- `motion_arrived` 与 `task_completed` 分开；后者只指当前接近子目标，需数值目标和可见对齐同时成立。不是抓取或整任务成功。
- 保留 `approach_step` 为相对位移调试函数，它不宣称任务完成。未引入框架或状态机。
- 保留上轮未完成的 placement.py 为明确标注的未验证工作代码，真实演练前仍需检查。
- 原生 Context/MCP、后端路径检查、权限、手动事实交接、失败后不重放的约束不变。
