# C-0.3.2：隔离环境FK与优先布局

来自 C-0.3.1 的独立候选；原版和冻结版本不变。只修规划接入和预算，不修改视觉判据、红块初始坐标复用、目标65mm中心距、几何/碰撞余量、SDK50%速度、关节/反馈容差或持稳时间。

1. 将宿主 services/piper/geometry.py 与固定URDF原样快照纳入任务git归档的 native_fk 包。保持代码与模型SHA校验、一次原生5姿态矩阵核对。实际bubblewrap环境无需导入宿主services；缺包/身份不符明确失败，不再静默回退数千次服务FK。报告记录实际FK模式及SHA。
2. 完整几何方案找到后，原生路径认证不再受候选搜索短时片限制；仍逐边保留原生碰撞/工作区检查及90秒全局预算。失败原生路径仍拒绝并缓存，短预算优先和长预算补查保留。
3. 保留按完整任务移动距离/可达性/绿色接近空间排序；不写死图像右侧。本轮第一候选就是红块右侧，在服务耗时下不再被验证阶段的短预算提前丢弃。添加布局名次、橙块XY搬运距离与FK身份记录。不是全局最优规划宣称。

验证：411项回归、52子测试；19种摆位完整规划和衔接路径检查；使用生产blocks_runner生成的bubblewrap命令、独立Python运行时、无宿主services访问的两进程离线回放。只接离线NoOwner后端的FK/IK/路径白名单，无真实机器人socket或硬件命令。
最新144325摆位：线上旧版49.10秒、2142次FK服务、选择左侧；新版隔离回放6.92秒、一次FK批量校验、选择右侧；额外每RPC4ms回放8.75秒仍选右侧。离线时间不等于实机保证。XY搬运目标距离278mm降至155mm；原红块坐标保留。实机正确率待操作者测试。

已知独立限制：旧Web成功仅代表既有控制器返回完成，旧末帧实际未叠好；这次未扩大视觉改造范围，也不把离线成功计为真机成功。正常场景复用不重新测量红块；已知实物移动仍不能作为可靠的旧坐标证据。
