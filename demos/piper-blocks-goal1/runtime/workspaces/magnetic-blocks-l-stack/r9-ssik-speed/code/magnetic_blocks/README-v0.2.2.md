## 视觉与重复支撑判断

正常路径优先由普通 Python 使用已核验的路径、实测 FK、当前 RGB、标定投影和同轮物体关系给出“放置大体合理”的判断。允许部分遮挡，不要求完整轮廓、隐藏底面或接触力证明。头部看不全时，腕部中央物体区域可以补充证据；退开后主要检查物体是否仍在已放置的位置，并有可见的底层参照。无法判断仍返回 unknown，明显高度/位置矛盾返回失败。

下降结束的正面支撑判断可在同端点、同 Owner/标定/几何、30 秒内复用；释放前仍取得当前图像检查明显变化。窗口不满足时，先用当前普通规则重新判断，不强制调用 Gemini。没有改变原生 IK、工作区、碰撞、夹爪和关节到位检查。

`main(ctx, allow_auxiliary_vision=False)` 默认不调用 Gemini。必要时可显式设为 True，或 CLI 加 `--allow-auxiliary-vision`，只在普通规则无法判断时允许辅助视觉。明确负面不会靠再次问模型改成正面。默认无法判断会保留现场、返回缺少的事实，不能盲目重放动作。

R8 五个历史检查点（橙下降、释放后、退开，绿下降、释放前）用原图和固定 URDF 的离线 FK 回放均获得普通规则的定性通过；没有调用 Gemini。历史回放关闭的是墙钟新鲜度验证，原帧及时间戳未改，不能作为当前现场证据。此规则不能保证识别所有倾斜、滑移或隐藏接触，也未经过新摆位真机统计验收。

## 绿色逐函数恢复

`verify_completed_action(ctx, previous_report=...)` 现在支持绿色下降、释放、退开。它只做核验，不发动作：

1. 验证已完整执行的全部原生回执、最后请求 ID、Owner、当前位置和计划动作数。
2. 保留原始报告，核对支撑来源和历史哈希；重新取得当前图像。
3. 用当前定性规则核验端点，保存带来源哈希的新恢复报告。
4. 只在恢复报告成功后，把它作为下一函数的 `previous_report`，继续释放或退开。

```python
from rehearse_step import run_one

r = run_one(ctx, "verify_completed_action",
            {"previous_report": "本轮/失败端点.json"},
            "本轮/新的恢复报告.json")
# r['result']['ok'] 为 True 后，才把新的恢复报告交给下一函数。
# support_report 仍使用本轮最初绑定的支撑报告，不能换成别轮文件。
```

已到位且控制确定的绿色端点，若仅结果图像判断未通过，不再额外发送会切断控制交接的 Hold；当前位置继续持位。真实动作故障、回执含糊、未完成、Owner 改变、已经发生 Stop/Hold 或证据被改动，仍不能通过此入口恢复。原动作不会重放，main 不会自动重新跑一遍。释放前拒绝、尚未发动作的情况，应解决前置条件后调用该函数，而不是伪装成“完成动作恢复”。
