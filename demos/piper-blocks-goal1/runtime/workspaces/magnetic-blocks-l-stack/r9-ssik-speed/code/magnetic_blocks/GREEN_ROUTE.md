## 本次修改

- `GreenPregrasp.prepare` 从实际观测、当前owner、已完成动作回执、同轮
  场景来源和指尖模型建立规划输入。该验证在搜索前完成一次。
- `planned_green_path` 只计算显式关节、几何、IK、原生CAD/workspace和
  指尖路径；不读取图片、不查询owner、不修改时间戳，也不产生运动许可。
- `green_route.choose` 在既有180–240mm悬停范围内，同时搜索高度和
  小角度朝向。用当前T_flange_tcp补偿法兰XY，保持原始测得的绿色接触中心，候选方向是基坐标X/Y轴±2/±4度。
  仍保留近似向下约束(Tzz<=-0.995)，并检查整条插值路径。
  本次扩展的是接近姿态/路径；没有盲目改变夹持中心，也没有更换目标积木坐标。
- 优先寻找原20mm标定余量之外至少3mm的规划余量；再检查同一朝向下
  高度±1mm两条完整路径，避免接受单个贴边解。最多117个候选，搜索超过25s后不再启动下一候选（不打断在途只读调用）。
  原生关节限位、状态容差、工作区、碰撞与图像10s期限不变。
- 检查从候选悬停到既有top+128mm插入高度的分段IK、CAD/workspace、
  近似向下姿态和指尖/桌面关系。该前瞻不证明接触或夹持；真正下降仍走原函数
  的实际观测、路径及必要的定性判断。
- 选中后实际获取一组RGB观测，验证同一owner、已完成动作、姿态和场景
  是否仍一致；小的合法反馈变化用当前状态重新计算路径，而不是复用旧碰撞许可。
  不强制重新测深度或语义定位。执行函数再次从实际状态检查。
- 未找到路径时保留候选拒绝摘要，报告规划失败，不把它伪装成缺少深度。
