# c-Four 1.0 · 四积木独立候选

目标结构为黄色叠绿色、绿色叠红色，橙色与红色并排。延续此前底层左右顺序可交换、整组可平移的约定。不是任意参考图自动解析器；这个版本明确实现上述支撑关系。

## 来源与入口

- 基于 `C-speed-0.3.2-retreat-r1`，源提交 `c895a2587a06e726539e103959d8c8862711e9df`。
- 5090 独立目录：`/home/ubuntu/code_junqi/rax-piper-franka-20261104/experiments/blocks-c-Four10-20261116`。
- 新入口仍为 `assembly_controller.main(ctx)`；保留原生单 Context、初始定位、整段预检、按边界执行、回执与按需观测的组织方式。
- 旧的 `controller.main` 及历史 R8 演练函数作为来源资料保留，不能作为四积木入口调用。
- 原工作版、冻结版及当前 Web 指向均不替换；本次不下发任务动作。

## 适配范围

1. `task_spec.py` 集中声明四颜色及 green→red、yellow→green 支撑依赖；初始定位缺任何一块均不能静默当三块任务成功。
2. 基于本轮实际图像区分橙色和黄色 HSV；黄色与其他块一样进入初始三维定位、保留场景、运动碰撞和执行结果检查。
3. 保留原底层布局/顺序搜索，补齐第三层的放置、张爪、退开及下一次抓取空间的提前预检。
4. 标准近竖直姿态之外，为黄色增加围绕夹爪开合轴的 ±15°、±25° 姿态候选。按 TCP 与实测刚性抓取关系计算法兰目标，而非把法兰当积木中心；保持积木直立的目标关系。新倾角抓取尚未经过真机验证。
5. 第三层退开高度根据工作区剩余空间产生候选，必要时横向退开；各段继续经过相同的几何和原生碰撞检查。
6. 多块衔接时增加“保留当前朝向离开已放物体，再转向下一个物体”的空载候选；避免把静止位置无碰撞误当成原地转向也无碰撞。
7. 延续张爪反馈 72–74 mm 预检覆盖和指尖近物体比较 1 mm 误差策略；不允许接触/穿透其他物体，不新增运动跟随或到位容差放宽。
8. 主 Agent 和 Gemini 不参与正常路径预检；辅助视觉仍可按原接口显式开启，默认关闭。

## 离线复现

在上述 5090 独立目录，用现有环境运行：

```bash
/home/ubuntu/code_junqi/rax-piper-real-ffs-20261025/.venv/bin/python verify_isolation.py \
  --case blocks-C-speed032-20261116/web-main-20261116-143925-54efd0
```

这个命令只进行离线预检和轨迹预览，不调用 `main` 的硬件执行阶段。`--case` 选择已存在的 API 沙箱模板，实际几何输入始终来自本目录的 `INITIAL.json`。

本版本需要宿主侧 `installed_collision_math.py` 的对应比较误差支持；它已随独立目录保存，但未替换运行中的原宿主模块。不可只拷贝一份 `main` 就假定所有依赖均已接通。
