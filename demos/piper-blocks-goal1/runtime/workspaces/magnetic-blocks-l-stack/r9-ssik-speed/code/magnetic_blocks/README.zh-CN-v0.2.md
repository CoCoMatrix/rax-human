## 按照什么流程合并

参考 [Franka autonomous-control](https://github.com/robot-agent-exploration/rax/blob/real/franka/agent_skills/task/autonomous-control/SKILL.md) 和 [rax-compose-and-test](https://github.com/CoCoMatrix/rax-skills/blob/main/skills/rax-compose-and-test/SKILL.md)：逐函数演练后，把 Agent 在函数之间临时计算、传递的信息写成普通 Python 输入计算，再在同一个 ctx 上串联函数。运行期间正常步骤之间不调用主 Agent；保留函数现有检查和 Gemini 调用。

顺序：当前场景与空载状态核对 → 张爪、空载过渡 → 橙块接近、闭合、试抬、搬运 → 在红块旁放置、释放、退开 → 绿色入口与支撑位置确认 → 绿块接近、闭合、试抬、分段搬运 → 放到红块上、释放、退开。

这次没有拼接连续轨迹，也没有删除检查或优化观察频率。原来 31 个函数及 8 个检查模块保持不变；新增部分是 main、当前摆位输入计算、报告串联及必要的数据契约适配。绿色第一次横移保留 R8 的绕行关系：维持当前 X/Z，移动到本轮已放置橙块 Y−105 mm，随后抬高并分段到红块上方。

每轮初始位置来自当前观察，搬运和放置使用本轮三维目标、实际抓取偏差及 FK，不回放历史固定 XYZ。可适应摆位变化是设计目标，尚未经过合并后的多摆位真机验收。

## 调用方式

从工作区根目录运行。查看预览不会创建硬件连接：

```bash
python code/magnetic_blocks/controller.py
```

由原生 RAX 宿主提供已接入的 ctx 时：

```python
import sys
sys.path.insert(0, "code/magnetic_blocks")
from controller import main
report = main(ctx, output_dir="output/composition/runs/本轮唯一目录")
```

`main(ctx)` 本身是实际执行函数。CLI 默认只预览，明确加 `--execute` 才执行；此次没有执行该入口。开始条件沿用本机 XPolicy Prepare、左爪空载闭合，不能直接从上轮持物末状态调用。宿主负责设备唯一占用、使能、停止及回 Prepare。

首个失败即返回部分报告，记录停在哪一步、持物是否确定、动作是否已有回执。不会自动松开、回零或盲目重跑 main。各阶段耗时、工具耗时、动作回执及辅助视觉次数写入本轮 REPORT.json；主模型运行调用次数明确为 0。

## 根据 skill 的优化分析——本次未实施

1. **支撑判断重复且可能矛盾。** 橙块下降和释放的两次辅助视觉分别约 7.53 / 9.82 秒；绿色分别约 6.26 / 5.93 秒，并出现相反判断。优先研究同一未变化边界证据的有效复用，保留异常和明显不稳定时的停止；不能把历史人工确认写成未来永远通过。
2. **主模型等待与大上下文。** 合并版已移除正常函数之间的主 Agent 决策。R8 函数报告可达约 430–492 KB；后续可保留完整原始文件，给调试 Agent 提供简明摘要和引用，减少重复读源码和历史图片。
3. **观察与检查开销。** R8 有 32 次显式 observe，合计约 17.60 秒，不含动作回执内取图；可分析哪些边界能消费刚返回的观测。864 次 FK 合计约 3.23 秒、24 次显式路径检查约 5.30 秒，不能仅看调用多就认定是主要瓶颈。
4. **动作连续性。** 先测清预检、交接、执行、持稳各耗时，再判断能否减少空载小段。此次保留 R8 分段，不改变闭合、试抬、释放边界，不改速度或容差。
5. **恢复和可复用性。** 绿色放置边界尚缺通用完成动作核验入口；按原生逐函数恢复思路补齐，避免故障后只能重新整段。把分散的相对距离整理成具名参数及已测范围，分别验证入口、观察位、整条搬运路径可达性。

R8 归档中 30 次函数调用累计约 261.18 秒，5 次辅助视觉累计约 34.56 秒；这些是演练历史数据，不是合并版实测总耗时，不能据此宣称已提速多少。下一阶段应从重新摆放的场景运行一次 main，再比较耗时、模型次数、失败位置；多次不同摆位成功后才评价泛化。
