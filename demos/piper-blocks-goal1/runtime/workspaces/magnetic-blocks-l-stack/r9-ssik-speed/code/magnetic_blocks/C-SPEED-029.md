# C-speed0.2.9：多种子、抓取姿态候选与按实际搬动物体规划

父版本0.2.8及冻结版本保留。主机控制/标定/几何资产不变，新增独立可写控制器。保留RAX main(ctx)和现有普通代码预检，不增加任务框架或正常路径的模型调用。

## 本轮问题与修改

原预检在选布局前强制三块积木都能被抓起，只在一个固定抓取位置、竖直向下、零位种子下变化12个yaw；红块全失败后直接淘汰全任务。这不覆盖红块原地作底座，也不覆盖小幅倾斜抓取。

1. 布局先确定哪些物体需要搬动，未搬动的红块不再必须通过源抓取IK。保留底层与待抓绿色积木的真实包络检查。目标位姿不再用单一竖直终点筛掉后面的倾斜候选，完整搬运放置路径仍必须提前验证。
2. 每个pose优先当前种子；失败后尝试邻近已验证解和两种确定性的肩肘姿态。按pose、seed、预算缓存结果，短预算5ms优先，仍保留100ms补查与全局90s上限；传输/接口错误不当作IK失败重试。
3. 原竖直姿态优先，必要时增加抓取高度±6mm，以及绕径向正交轴±3°、±5°倾角，优先向内倾斜。利用140mm TCP围绕杯块顶面以下12mm接触中心生成法兰姿态，不是只倾斜相机/坐标而忘记TCP偏移。远端扩展候选优先验证较低正上方入场，再考虑偏移路径。
4. 倾斜抓取使用真实求解的刚性夹持变换，四分之一转向保持积木直立；放置法兰位置由目标物体位置与实际夹持变换反求，不能继续机械套用top+128mm。抬升、载荷、下降、松爪、退开及速度衔接仍经过同一原生路径与任务几何检查。
5. 提前淘汰已经确定的源碰撞。对于未求出的IK，不把它误写为物体物理不可达。第一条经过完整验证的路线即可返回，不为了穷尽组合继续等待。

## 开源参考与取舍

- [MoveIt Task Constructor](https://github.com/moveit/moveit_task_constructor)：参考独立GenerateGraspPose、ComputeIK和连接阶段，以及不同IK解/候选之间传播结果的方法。[官方抓放教程](https://moveit.picknik.ai/main/doc/tutorials/pick_and_place_with_moveit_task_constructor/pick_and_place_with_moveit_task_constructor.html)。本次采纳方法，不将整个MTC框架嵌进RAX。
- [TRAC-IK](https://github.com/traclabs/trac_ik)：公开实现结合不同数值求解方法改善关节限制下的局部收敛，但明确不代替碰撞检查。这个改动的关键是增加合理的任务位姿候选，仍使用本项目已验证的KDL工具；本次没有更换求解器或引用项目宣传的成功率当作Piper成功率。

## 离线证据

原103654摆位：红色顶面(378.457,-337.495,77.272)mm。原预检2.323s后24次IK失败，未发动作。
新版同一摆位3次完整原生预检为8.997、9.047、9.017s，每次758次短预算IK、1次FK批量校验和27次原生路径检查；所有方案相同：橙→红→绿，组装红块中心XY=(320,-80)mm。红块抓取选择向内倾斜5°，法兰约(369.351,-329.374,204.739)mm；不是降低碰撞限制后通过。

每次包含完整抓放退开检查、4组速度衔接曲线验证、闭爪前现有数值几何接口、放置后物体位置误差小于1mm以及积木保持直立的变换核验。另两轮历史摆位通过（14.655s、6.904s），未使用倾斜候选。637项测试+52项子测试通过。专门测试了红块原地无需红块抓取查询、不同种子回退、TCP中心、倾斜夹持后的放置变换及错误不被吞掉。

验证进程禁止设备状态访问，拒绝所有非FK/IK/路径预览工具，阻断网络；hardware_dispatches=0。这是离线完整模型验证，不是新的真机成功率，也不能保证任意摆位有解。物体位置可达、完整抓取姿态可达、带载完整路径可达是不同条件。

原80%机械臂速度、25mm/s夹爪速度、0.1rad运动跟随、0.01rad到位/绑定等配置未改。相机过期恢复继承0.2.8。
