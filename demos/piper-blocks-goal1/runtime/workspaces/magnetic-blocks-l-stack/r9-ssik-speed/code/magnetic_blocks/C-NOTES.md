# 积木 C-0.1：非共线摆位与完整任务可达性

这是从 B-0.7 独立复制的可写测试版。入口为 `assembly_controller.main(ctx)`，保留原生 RAX 的已合并函数执行方式，不启动主 Agent，不新增逐阶段 Gemini 调用。B 版与已有冻结版本不改。尚未进行 C 版真机验收。

## 改动

- 输入仍为每轮初始 RGBD 的红、橙、绿三维位置，不要求共线、固定颜色顺序或人工输入位置。
- 最终保持原图结构和方向：绿在红上，红橙在同一底层并排；允许左右互换及整体平移。
- 布局候选覆盖已配置的工作区与已建模桌面交集，包括原位置、场景中心、平移位置和工作区网格。扩大的是实际搜索覆盖，不改 URDF 关节限位，不把工作区方框当作可达证明。
- 抓取朝向覆盖四个正交面及小幅偏角。每个候选继续通过 FK、完整位姿 IK、安装几何/FCL、夹爪、负载和桌面检查。
- 搬运悬停高度由积木高度、邻近物体、最低间距与优选余量产生，保留较低的合法高度候选，不再只有少数绝对高度。优选余量只是优先级。
- 搜索前先排除源积木抓取/悬停不可达；放置与张爪终点、后续绿块起抓冲突提前检查。不会先实际抓起再发现后续无解。
- 一个布局/顺序只使用有限预算，避免耗尽整个预检；保留 KDL 短预算筛选、长预算补查及已验证结果缓存。
- 直接路径仍先尝试；其余通道用便宜的笛卡尔负载包络估算排序。估算不接受或拒绝运动，真正执行方案仍逐段完整检查。
- 超过原生 600 点的批次在发动作前分解并验证成较小连续批次，尽量保留速度衔接；不提高底层上限，任何下发异常仍停止，不能自动重试。
- 优先给后续绿块留出空间，但“优选空隙”不作为新的绝对拒绝门槛。

## 保留的配置

SDK 50%，抓取目标 50 mm（实测接触范围 48–54 mm），开爪 73 mm，夹爪轨迹 15 mm/s，关节反馈/状态绑定 0.01 rad，持稳 0.3 s。保留 B 版抬升→搬运的底层批量/速度衔接以及闭合、下降、释放边界。原生 400 mm 单段范围、工作区、碰撞与停止约束不变。

## 使用范围

可规划位置由“抓得到、能离障、能搬运、能放置并张爪退开”共同决定；某个点在机械臂标称半径内不表示全部姿态都可达。此版针对三块直立、尺寸约 60 mm、能被现有感知识别的积木。不会承诺任意相互重叠、紧贴、被遮到无法定位或模型外障碍的摆位都能成功。

验证使用已安装的真实 KDL/FK/FCL 后端、历史反馈和合成新摆位；禁止网络/owner 与动作工具，硬件下发次数为零。完整覆盖结果、耗时和版本哈希见 OFFLINE-VALIDATION.json 与 VALIDATION.md。离线通过不是实物摆位成功记录。

## 真机入口

新工作区：`runtime/workspaces/magnetic-blocks-l-stack/C-0.1-layout-coverage`。

主执行入口：`code/magnetic_blocks/assembly_controller.py:main(ctx)`，继续由既有运行器提供同一个 `ctx`，不可直接在普通 Python 中创建第二套控制器连接。

本次仅准备独立候选，当前 B 版 Web 不自动切换，不连接硬件、不回零、不发送任务动作。
