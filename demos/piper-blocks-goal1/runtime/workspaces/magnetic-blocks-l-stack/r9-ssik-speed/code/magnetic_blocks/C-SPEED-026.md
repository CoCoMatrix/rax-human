# C-speed0.2.6：几何容差、远端路径与动作衔接

这是 C-speed0.2.5 的独立后继测试版；原 main、旧运行环境和已有冻结版本保留。没有发出真机动作。

## 这次失败的原因

2026-11-13 的 `web-main-20261113-183638-2e5468` 初始定位通过，但整段预检 90.05 秒超时，共 4,041 次 IK 查询，约 66.40 秒花在 IK。指尖／红块 19.481 mm、负载／红块 19.269 mm 被原 19.500 mm 门槛拒绝。这些数值是第一个拒绝采样点，并不代表整条路径的最小间隙。

单独加大容差仍不足以解决该摆位：旧布局排序优先保留红块原位，容易占用远端物体向内进入的通道。另一种远端橙块排列还暴露了低位入场候选过少、单一空载抬高量、在低位提前转向以及中间点贴着验收下限生成的问题。

## 修改

- 在原几何误差基础上额外允许 1 mm，规划、执行、批量轨迹实际采样检查使用相同政策；原生执行路径的左指尖／任务障碍物检查同步更新。
- 完全相同的起点、目标、姿态、场景和检查选项复用连接结果与失败结果；快速 IK 失败不会污染长预算补查。相同搬运终点候选去重。改变场景或原生检查发现新冲突会使相关缓存失效。
- 根据所有远端物体的位置给目标布局排序，优先留下向内通道，不限定绿色。保留整体平移、两种底层左右布局和原布局候选。
- 路径仍先试直接连接；补充低位向内、分段上升、障碍物侧面中间点、保持抓取朝向先移入后转向。中间点优先留余量，最低间隙与优选余量分开。
- 空载低位入场不再只试前三个中间点，细化可达边缘附近的候选，并尝试保持当前朝向先抬高 5/10/20 mm。具体是否采用由完整路径检查决定。
- 抓取后的实际位置偏差不超过 1 mm 时，批量执行先用实际起点、实际负载关系校验已有候选轨迹，避免无条件重新求解离开路径。未通过时仍走原有重绑定／独立段检查。这里的 1 mm 是优化分支选择条件，不是拒绝稍大偏差的门槛。

参考了 [OMPL LazyPRM 的连接验证与缓存方式](https://github.com/ompl/ompl/blob/main/src/ompl/geometric/planners/prm/src/LazyPRM.cpp) 和 [MoveIt Task Constructor 的连接阶段组织](https://moveit.picknik.ai/main/doc/concepts/moveit_task_constructor/connecting_stages.html)。仍使用现有 KDL、RAX main 和 Piper 接口，没有引入新的规划框架。

这些间隔没有主模型思考或辅助视觉调用。开爪到首段空载进入的间隔为 4.517 秒；其中有路径检查。部分下降动作的原生预检约 0.149–0.178 秒、控制交接约 0.07–0.10 秒、回执发布约 0.055–0.076 秒。现有 0.3 秒持稳窗口仍保留。

抬升→搬运原本已经启用批量速度衔接，本版减少重复求解并继续检查实际编译轨迹。闭合、接触下降、释放不强行跨边界拼接。实际动作间隔是否缩短，需下一轮真机日志验证；离线计算时间不能当成实机节省时间。
