### 一次下降如何检查

从本轮实际悬停状态、保留的三维积木位置和当前四元数求解终点IK。对真实关节插值路径做至少41点、相邻关节间隔不超过0.002rad的FK检查：近似向下朝向、原12mm中心走廊、原邻块分离范围、接触深度、完整指尖相对桌面的原12mm名义间隙、单调下降和工作区；再调用原生CAD/路径检查。

先尝试一段；未通过时，在**发动作前**尝试从原路点中选择更细的分段。数值搜索内部不获取图片，也不调用模型。执行后的分段续接使用真实反馈重新核对剩余路径，不伪造中间观测。若动作或回执失败，停止而不自动重放。起点和到达夹持位仍做原有定性对齐判断；闭合、试抬和释放检查保留。

本轮实际FK/IK求得的一段路径通过了原有条件。关节插值不等于直线TCP路径；仅看两个端点不足，因此新增检查覆盖路径中间。不能据此宣称任意新摆位都能一段下降。

### 一次完整张闭爪

独立工具 `piper_gripper_stroke(width_m, direction)` 使用现有单调五次曲线，在同一个Owner请求里完成全行程；左右臂和右夹爪固定。左爪仍有75mm物理命令上限、原10mm/s速度和原力设置。普通 `piper_gripper` 的10mm单次限制保留。

任务层仍先验证完整张开扫掠、入块位置或释放支撑事实，再调用完整行程。闭爪目标仍是积木经验的50mm，释放/打开仍69mm；并未套用蓝杯的3mm。10mm试抬仍保留。

### 减少交接等待

复用蓝杯v0.6已实现的两项机制：独立Owner在`rax_motion`完成状态改变时立即发布；同请求、同Owner、状态一致且完成后0.5秒内，可复用已完成的0.3秒/至少4样本持稳证据。过期、不一致或取图重试时重新持稳。动作后默认RGB，后续真正需要度量深度时再请求。关节到位/观测绑定0.01rad及夹爪的独立米制容差保持。

### 速度50%

原积木成功版实际上使用`standard`：SDK10%，规划关节速度上限10°/s、加速度20°/s²。根据本次追加要求，新候选的`WORKSPACE.json`启用已有`faster`：SDK50%，规划上限20°/s、加速度40°/s²，保留15%跟踪余量，实际规划关节峰值不超过17°/s。夹爪仍10mm/s，原生Prepare速度不改。

相同47条历史路径的数值重定时，原生轨迹时长合计126.600秒→89.833秒；这组对照**只改变速度、尚未算入减少分段**，并非main的真实耗时预测。新SDK设置没有执行过真机；不能把百分比变化理解为实际速度五倍或成功率已验收。
