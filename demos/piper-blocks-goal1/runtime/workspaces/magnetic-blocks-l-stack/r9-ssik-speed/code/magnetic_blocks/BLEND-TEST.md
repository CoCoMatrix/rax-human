# 独立积木速度衔接测试版

原v0.2.9、v0.2.10、v0.2.11以及冻结版本保持不变。本目录有独立backend、bridge及Owner源码，自别名指向本目录；没有启动硬件或切换原Web。

## 两个入口
- controller.main(ctx)：恢复原多个函数分段执行（group_empty_entry=False）；保留自适应入口高度、分段比例和50%速度。
- controller.main_blended(ctx)：同一任务及接触边界，开头3个空载路点保留各自plan_segment接口/报告，底层通过一条多路点ActionChunk执行，前两个路点作速度衔接。不是三个函数分别持稳后还能无停顿。

闭爪、试抬判断、释放保持独立，不拼入轨迹。已有接近已为一次下降，没有内部路点可以衔接；其余带载/支撑阶段暂维持原来的状态依赖，不为连续性取消检查。

## 曲线与验证
复用蓝杯v0.6五次Hermite路线，指定路点非零速度、零加速度，首尾停稳，反向关节速度归零。限制偏离原直线<=0.01rad，真实float32 30Hz轨迹、物理关节限位、速度/加速度、600点上限、FK工作区、全CAD、测量桌面及积木碰撞检查。再用安装指尖检查真实曲线及中点，不以端点IK代替完整路径。
原60°单段上限、50%SDK速度、0.01rad状态/到位容差、0.3秒末端持稳保留。反馈检查沿已下发轨迹进度，异常Stop后不可自动重放。
本轮场景离线结果：439点、14.633秒，两内部路点速度非零；预览与执行层生成的wire完全一致。此时间不含启动、定位、预检等，不是实测总耗时。

## 橙块试抬停止原因
web-main-20261112-151647-6cde07：Owner日志实际36条SDK完成回执，桥接层已接收36条后报unexpected dispatch receipt；最终J4误差约0.00131rad，在0.01rad内，Gemini0次。
受控Policy的predict线程与watchdog并发读同一个ReceiptTail游标，读取和交付原先没有一起加锁。离线强制并发复现重复交付。现用同一transport RLock包住完整读取+交付，保留真实重复/乱序/身份/目标不一致拒绝，没有吞掉错误回执或放宽容差。
201项任务测试、50项曲线/执行/并发及完整夹爪工具测试、93项接口/持稳/生命周期测试通过。蓝杯20mm专用闭爪4+5项不适用于本任务，使用积木完整stroke测试覆盖，未套用蓝杯3mm参数。

## 使用与限制
必须通过本目录scripts/piper_explore.py装配新会话并显式使用此candidate；不能把任务文件单独拷入旧宿主就认为回执修复及衔接生效。新摆位初始重新定位。若发生含糊执行结果，先核验原生Stop/当前负载，不自动执行main、松爪或Prepare。
此版本只离线通过，没有真机速度、跟踪或成功率结论。现场下一步先测试分段main验证回执修复，再明确选择main_blended进行受监督对照。记录两内部路点间隔、首末SDK回执、规划/运动/持稳/图像时间和总耗时。
