# 搭积木：三块磁性积木组成 L 形

## 目标与完成条件
参考 references/target.jpg，将当前桌面散落的积木组成目标结构：
- 红色在底层左侧，橙色在底层右侧，二者均由桌面支撑，侧面相邻靠拢，前面大体齐平。
- 绿色放在红色正上方，底面由红色顶面稳定支撑，大体对齐；不是跨在两块底座之间。
- 最终夹爪释放并退离，三块保持上述结构，无明显倾斜、滑移或被夹爪继续支撑。
- 照片定义相对布局，不提供桌面实测坐标、世界方向、精确尺寸或相机标定。不要追求像素级复刻或白色圆形装饰的精确转角。

## 操作范围
复用现有左 Piper 接口和三路相机。右臂不参与搭建，保留状态/碰撞监控。
用户已要求开始本轮探索，并确认空载、两臂/夹爪无接触、运动区域无人且可立即急停。宿主负责接入与授权；Agent 不自行使能或回零。先核对当前状态并取得本会话新观测，再按原生 manual-robot-control 探索。
Prepare 由宿主 XPolicy 执行，不交给任务控制器。

## 尺寸和初始策略：用户提供，尚未在本任务验证
- 用户测述长、宽均约 60 mm，有微弱磁性。高度、实际接触面、突起和磁吸方向须用当前观测/测量核对；不能将 60 mm 当成精确全尺寸。
- 底层并排时，优先从积木的前后相对面夹持，让左右拼接面露出，再沿底层并排方向横向靠拢。
- “前后/左右”是目标结构的局部方向，必须根据当次布局映射到机器人坐标，不固定等同于基座 X/Y。
- 上层绿色可正常对向夹持，定位到红色上方后下降放置；夹爪退开方向需不扰动底层。
- 横向靠拢优先保持积木受控、避免指尖挤在两块之间。是否先落桌再短距调整需要探索验证，不预设可以在桌面拖动。
- 弱磁性可能辅助贴合，也可能吸动邻块或在松爪时牵连。磁吸不是已稳定支撑/已夹稳的证据。
- 夹爪开度、闭合量、夹持高度、试抬高度、接近速度和放置偏移均需针对积木确定；不继承蓝杯专用数值。

## 感知与函数组织
初始从当前图像识别红/橙/绿积木，结合有效深度测量位置、朝向和可用搭建区域。
普通颜色/轮廓/深度与控制反馈优先；只在语义、关联或可见结果不能可靠判断时使用辅助视觉，不为每个动作固定增加模型调用。
几何与控制反馈负责数值到位和已建模碰撞；图像负责可见物体关系、夹持、磁吸扰动、支撑和最终结构。不要要求端点图像证明隐藏面的毫米间隙或期间从未接触。
头部外参仍是现有 provisional 标定；左腕 FFS 仅有相机光学坐标，未做手眼标定，不能直接用作基座目标。
后续将探索成功策略整理为有输入、有前置条件和结果的函数，逐函数演练后组合 main(ctx)，再进行新摆位整段测试。
每次记录阶段耗时、主模型/辅助视觉调用数、结果与人工协助；现在没有任何已验证成功的搭建动作。
